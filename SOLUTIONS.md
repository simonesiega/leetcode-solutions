## Complexity Notes

Each complexity is derived from the implementation in the linked file rather than from the problem's theoretically optimal solution. The variables used in a row are defined in that row—for example, `n` may represent the number of array elements, while `m` and `n` may represent the lengths of two different inputs.

Time complexity describes the worst-case running time unless it is explicitly labeled **expected**. Dictionary and set lookups, insertions, and deletions are treated as expected `O(1)` operations, consistent with Python's hash-table behavior.

Space complexity describes auxiliary memory used by the algorithm. Memory required for the returned result is excluded unless the row explicitly includes it. When an implementation sorts a Python list in place, the analysis includes Timsort's temporary memory where relevant.
